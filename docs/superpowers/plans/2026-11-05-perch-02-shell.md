# Perch plan 2: the shell

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Perch looks and behaves like its own browser. The chrome follows DESIGN.md's five themes and five accents, the tab strip, toolbar and profile menu are restyled, hide-chrome mode and split view work, Brave is the default engine with Tab for Google, Google-bound background traffic is gone except the allowed connections (each with an off switch), incognito keeps nothing, the memory saver follows Lulltab's rules, the `extension/` features and Backrow ship built in, and the native features from spec 5.9 that the extension could not do (command bar, tab tools, Spaces, HTTPS-only, DNS over HTTPS, fingerprinting defaults, on-device translation) are in. The owner checks DRM playback on the real build.

**Architecture:** Plan 1's pipeline stays: an `overlay/` of whole new files, a `patches/series` of small diffs, and generators, replayed onto the pinned tag (Chromium `158.0.8127.18`, checkout at `/Users/Shared/chromium-perch.noindex`, set in `perch-build.local.json`).
- **New code lives in `overlay/chrome/browser/perch/`**, one `BUILD.gn` with a `perch` source set, plus `perch_unittests` and `perch_browser_tests`. Patches only add call sites into it.
- **Perch's own headers** carry command ids, pref names, feature lists and strings, so a Perch change never edits a header that hundreds of Chromium files include.
- **Perch's pages** are the existing `ui-pages/` build, served from a `chrome://` WebUI data source. A small C++ handler answers the methods the browser owns: appearance, privacy, memory saver, command bar and site data. Everything perchd owns waits for plan 3b.
- **Defaults** come from two hooks: one adds feature overrides below the command line, the other sets pref defaults after registration. Most privacy work is a line in one of those two lists rather than a patch.

**Tech Stack:** C++20 and Objective-C++ in Chromium's tree, GN, gtest and browser tests run headless (`HeadlessModeBrowserTest`). Python 3.12 (`perch-build`), pytest. TypeScript, Bun and Vite for `ui-pages/`, `ui/scripts/gen-tokens.ts` and `extension/`.

**Spec:** `docs/superpowers/specs/2026-11-02-perch-design.md`, sections 5.1–5.9, 6, 13 and 15 step 2. Roadmap: `docs/superpowers/plans/2026-11-03-perch-roadmap.md`. Design: `DESIGN.md`. Earlier tracks this plan finishes: `2026-11-05-perch-extension.md` (component extension, native-only features), `2026-11-05-perch-ui-pages.md` (browser half of page hosting), `2026-11-05-perch-import.md` (opening tabs asleep).

## Global Constraints

- **Never build without owner approval for anything above S cost** (see the cost table). Builds run through `perch-build build`, which already uses `nice -n 15` and `-local_jobs 6`. Never chain two M or L builds without checking in. A full-core Chromium build shut the Mac down on 2026-11-04.
- **Never edit a widely included Chromium header.** That rules out `chrome/app/chrome_command_ids.h` (362 direct includers), `chrome/common/pref_names.h` (1,285), `chrome/browser/ui/ui_features.h` (599), `chrome/browser/ui/color/chrome_color_id.h` (302), `chrome/browser/ui/views/frame/browser_view.h` (710) and `chrome/app/generated_resources.grd`. Perch's own headers replace them: `perch_command_ids.h`, `perch_pref_names.h`, `perch_features.h` and `perch_strings.grd`. They are included only by Perch files and by the `.cc`/`.mm` files a patch touches.
- **Patches stay small and rebasable.** Each one is under about 150 lines, touches one Chromium area, starts with `# Perch: <why>`, and adds call sites rather than moving code. Logic goes in the overlay. New series entries go under `patches/perch/shell/`, in task order.
- **Tests run headless.** C++ browser tests derive from `HeadlessModeBrowserTest` (`chrome/browser/headless/test/headless_mode_browsertest.h`), and the build is checked with `--headless=new`. Never capture the screen or drive the GUI. The native chrome is reviewed through task 8's off-screen render. GUI checks are owner steps.
- **No new outgoing connection** unless it is on the allowed list (spec 5.1) and has its switch. `perch-build netaudit` (task 2) proves it after each privacy-relevant task.
- Owner priority 1 is speed. Nothing in this plan runs work on every page load that Chromium doesn't already run, and every Perch view is created lazily.
- Copy follows spec 6.6 and `~/ANTI AI WRITING.md`. Mac menu items use title case, as Chromium's do, and everything else uses sentence case.
- Commits use `type: description` with no attribution lines.

## Build cost

The first dev build (`out/Dev`, component build, 6 local jobs) ran from `gn gen` at 16:54 on 2026-11-04 to its last step at 01:34, about 8.5 hours. Each step below is labelled:

| Cost | What causes it | About |
|---|---|---|
| S | A few `.cc`/`.mm` files, a BUILD.gn source list, relinking | 5–15 min |
| M | Generated sources (grit headers, the DevTools protocol), a header with up to a few hundred includers, or the first build of a test binary | 30 min – 2 h |
| L | GN args, or a header half the tree includes. No dev step in this plan does this. Release builds are L | 8+ h |

Python, `ui-pages/`, `extension/` and `ui/` steps cost nothing on the Chromium side. Their output is staged into `out/<config>/perch_web/`, and only the grit and pak steps rerun (S).

## Review Focus

1. **A patch that stops applying on the next rebase.** Patches add call sites, logic stays in the overlay, and no patch edits a shared header. Each task's commit body lists the Chromium functions it hooks, so `docs/rebasing.md` can say what to look for when a hunk moves.
2. **Google-bound traffic after a privacy task.** `perch-build netaudit` (task 2) runs headless for 10 minutes on a fresh profile and fails on any host not in `build/allowed-hosts.json`. Tasks 3, 4, 7, 16 and 22 end with it.
3. **The Chrome Web Store and extensions keep working** (anti-goal in spec 4). Extension updates stay on, and a browser test installs a packed test extension. Task 3 must not borrow ungoogled-chromium's store-breaking patches.
4. **Incognito writes nothing to disk.** Task 15 compares the profile folder before and after an incognito session.
5. **A theme or extension theme fights the Perch theme.** Installing a Web Store theme replaces Perch's colours. "Reset to default" brings Perch's theme back, never Chromium's grey. Tested in task 9.
6. **Hide-chrome mode stranding the user.** ⌘L, ⌃Tab, the menu bar item and the shortcut always bring the bar back, including in full screen and with no tabs left. Tested in task 12.

### Task 2: Network audit

**Files:**
- Create: `tools/perchtools/netaudit.py`, `build/allowed-hosts.json`, `tests/test_netaudit.py`, `tests/fixtures/netlog-small.json`
- Modify: `tools/perchtools/cli.py` (add `netaudit [--minutes N] [--all-off] [--app PATH]`)

**Interfaces:**
- Produces:
  - `hosts_from_netlog(path: Path) -> dict[str, int]`, which counts URL_REQUEST and socket connect hosts from a Chromium `--log-net-log` JSON file. It handles the truncated last line that Chromium leaves when it is killed.
  - `check(hosts: Mapping[str, int], allowed: AllowedHosts, switches_off: set[str]) -> list[str]`, which returns the violations.
  - `AllowedHosts`, which maps each allowed-connection id (task 4) to host patterns. The examples are `extension_updates` (`clients2.google.com`, `clients2.googleusercontent.com`, `update.googleapis.com`), `safe_browsing_lists` (`safebrowsing.googleapis.com`), `components` (`update.googleapis.com`, `redirector.gvt1.com`, `*.gvt1.com` for CRLSet, certificate data and Widevine), `translation_packs` and `perch_updates` (`github.com`, `objects.githubusercontent.com`).
- Behaviour: `perch-build netaudit` launches `out/Dev/Perch.app` with these flags:
  - `--headless=new --user-data-dir=<tmp>` and `--log-net-log=<tmp>/net.json --net-log-capture-mode=Default`;
  - `--perch-netaudit-fast-timers`, a test-only switch that task 4 adds to make component and extension update checks start within 30 seconds instead of minutes;
  - and `about:blank`.

  It waits `--minutes` (default 10), sends SIGTERM, parses the log and prints one line per host with its allowed-connection id, or `NOT ALLOWED`. It exits 1 on any violation. `--all-off` first writes a `Local State` and `Preferences` with every allowed connection off, and then expects zero hosts.

- [ ] **Step 3: Baseline.** Run `uv run perch-build netaudit --minutes 10` against plan 1's build without the fast-timers switch, which is unknown so far and is ignored by Chromium. Save the host list in the commit body. It is the to-do list for task 3: every Google host on it needs either an allowed-connection id or a patch. **Cost: none** (no build).
